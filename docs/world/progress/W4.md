## Spec questions (minimal readings chosen)
1. Port ids stay numeric on the wire (1-based index in ports.json) so the protocol, `port:<id>:goods` keys
   and the client are unchanged; the string id is `key`. Ids are only stable per PORTS_VERSION (re-seed
   drops all port goods). If ports.json order changes, ids shift, which is fine because goods are re-seeded.
2. Safe zone: nothing on the server ever prevented damage near ports; `safeRadius` was only used as the
   (old) interaction radius. Kept as data, no gameplay effect (documented). A no-fire zone would be a new feature.
3. There is no respawn in the game (sunk = game over, new player); "respawn" = createPlayer/restorePlayer.
4. Spawn: jitter ±150 around `spawn`, min land distance 150 (spec says > 60 for generic spawns; > 150 for
   port spawn points). If no candidate qualifies, the port's spawn point itself (validated > 150) is used.
5. `isPlayerNearPort` in useGameState (one-line radius fix 200 -> 300) was touched beyond loadPorts because
   W5 had merged and it contradicted the dock rule.
